# Lộ trình phát triển (định hướng)

Cập nhật: 2026-10-11. Trạng thái hiện tại: v2.0 full-starter, repo Public, giấy phép PolyForm Noncommercial 1.0.0.

## Nguyên tắc

- Ưu tiên hoàn thiện lõi bản đồ/dữ liệu trước khi thêm miền mới (3D, AI).
- Module nặng (GPU/ML) chỉ triển khai như dịch vụ tùy chọn tách rời; không đưa PyTorch/dependency 3D vào máy chủ bản đồ chính.
- Giữ tách bạch giấy phép: mã nguồn dự án PolyForm Noncommercial; dữ liệu và thư viện bên thứ ba theo giấy phép gốc (OSM ODbL, Leaflet BSD, ...).

## Quyết định đã chốt

**Không tích hợp Map-Anything-v1 (tái dựng 3D từ ảnh/video) ở giai đoạn hiện tại.** Đánh giá 2026-10-11: MapAnything giải bài toán hình học 3D (point cloud, depth map, surface normals) — không bổ sung đường sá, POI hay dữ liệu hành chính cho Vietnam Atlas; tích hợp ngay chỉ tăng kích thước và chi phí bảo trì. Giấy phép đã kiểm chứng: mã nguồn MapAnything Apache-2.0; checkpoint `facebook/map-anything-v1` trên Hugging Face CC-BY-NC-4.0 — hai giấy phép phải giữ tách biệt nếu dùng sau này.

## Thứ tự ưu tiên

1. Ổn định lõi hiện tại (server stdlib + SQLite WAL + Leaflet + CI đầy đủ) — đang chạy.
2. Hoàn thiện polygon hành chính 34 tỉnh/thành (và cấp xã nếu khả thi) từ nguồn chính thống; không suy diễn địa giới từ điểm điều hướng/bbox. **Cập nhật 2026-10-11 (vòng C · T1):** nguồn polygon đã chốt — [`thanglequoc/vietnamese-provinces-database`](https://github.com/thanglequoc/vietnamese-provinces-database) (code/compilation MIT; hình học ranh giới gốc: "Vietnam Administrative Units Reference Map" — sapnhap.bando.com.vn, NXB TNMT&BĐ — Bộ NN&MT; tên/mã đơn vị: GSO; dataset v5.2.0 theo NQ 388/NQ-UBTVQH16, hiệu lực 20/09/2026). 34 polygon cấp tỉnh nhập vào repo (`data/provinces/provinces_34.geojson` — properties `code` = mã đơn vị hành chính GSO ("79" Hồ Chí Minh), `matinh` = mã GIS nguồn; `PROVENANCE.json` kèm sha256 từng file nguồn + attribution; tool tải idempotent `tools/fetch_province_polygons.py`), module `server/geo.py` (point-in-polygon ray-casting + bbox + resolve tên tỉnh mới/cũ/không dấu), tool `tools/report_province_coverage.py` — coverage theo polygon thật (không centroid-guess): **98,3% POI nằm trong 34 tỉnh; 1.724 POI (1,7%) ngoài polygon** (đảo/ven biển/ranh giới mơ hồ). Còn lại: cấp xã/phường (cân nhắc khi có nhu cầu thật — `phở việt trì` cần cấp thành phố). **Cập nhật 2026-10-12 (vòng C · T2):** geo-aware search đã tích hợp — cột `places.province_code` (GSO) + index, migration idempotent trong `init_db`; `save_place` tự gán qua `province_at`; tool `tools/backfill_province_codes.py` (dry-run mặc định, `--apply` backup trước): 96.893/98.617 gán được, 1.724 ngoài polygon. Query chứa tên tỉnh mới/cũ (`resolve_province` + subspan ≥2 token, vd `vũng tàu` ⊆ `bà rịa–vũng tàu`) scope theo `(province_code OR text tỉnh)`; ranking UNION hai nhánh giữ BM25 full-token cho pool text cũ rồi mới đến POI trong polygon (tên có dấu ưu tiên). `province=` param nhận mã GSO/tên/alias. Benchmark `after_round_c.json`: Hit@10 **99,26%** (135/136 — chỉ còn `phở việt trì`, cần cấp thành phố), MRR@10 0,914, Recall@10 0,866, geo_hit 4/4 coverage gap, no-match FP 0, p95 45 ms.
3. Nhập đầy đủ POI OSM (node/way/relation) + chống trùng theo `(source, source_id)`; giữ provenance. **Cập nhật 2026-10-11: bộ toolkit đã tích hợp (PR #3, `fc740e7`)** — fetch PBF kèm provenance/cache/retry, staging importer node/way/relation + snapshot + dedup, sync dry-run an toàn (online backup, retire propagation, bảo vệ bản ghi verified/người dùng), verify + export ODbL + packer; pilot 5.000 POI nạp thật đạt verify. **Full import 2026-10-11 (vòng A): nạp TOÀN BỘ PBF hoàn tất** — snapshot `pbf:full:retire=0` (source_date 2026-10-09): 93.617 inserted + 5.000 unchanged = **98.617 POI active** (node 64.367 · way 33.808 · relation 442); `verify_osm_snapshot.py --require-full` pass (cờ mới: chỉ pass khi tồn tại snapshot full-scope thật). Còn lại: lịch cập nhật định kỳ (mục 4).
4. Tối ưu tìm kiếm tiếng Việt không dấu, tile server/offline, quy trình cập nhật dữ liệu định kỳ. **Search quality 2026-10-11 (vòng A, `4a54a8e`):** xếp hạng **BM25** + **exact-name boost trong SQL** (cột `name_norm` + index; ưu tiên khớp tên chính xác không phụ thuộc cửa sổ fetch, phân trang ổn định) + **alias tiếng Việt** (bv/ks/dh/tp/tx/tt/dv/ubnd, dạng OR giữ nguyên token gốc) — thay sort `updated_at DESC`; bộ benchmark khóa `tools/search_benchmark.py` + `benchmarks/search_queries.json` (31 truy vấn) trên **98.617 POI**: Hit@10 **100%** (27/27), MRR@10 **0,975**, alias/category/exact/không-dấu đều 100%, no-match FP 0/4, p95 **17,06 ms** (ngưỡng đề ra: Hit@10 ≥95%, MRR ≥0.85, p95 <200 ms — đạt). **Vòng B (2026-10-11):** bộ truy vấn nâng lên **150 câu** (40 exact, 30 không-dấu, 25 alias, 25 category-theo-địa-danh, 20 tên tỉnh cũ, 10 no-match; version `round-b-150`) + metric **Recall@10** theo nhóm; API thêm `category` (1–20 prefix OSM, OR) và `near=lat,lon` (trả `distance_km` haversine, sort gần→xa khi không search) trên `/api/places` + `/api/export.geojson`; **phrase alias hành chính** một chiều cũ→mới từ `province_mergers_2025.json` trên ranh giới token ("sài gòn" ⇒ "hồ chí minh", "hà tây" ⇒ "hà nội" giữ OR cả hai phía). Kết quả `benchmarks/after_round_b.json`: Hit@10 **99,3%** (136/137 labelled), MRR@10 **0,889**, Recall@10 **0,851**, no-match FP 0/10, 3 truy vấn coverage_gap báo riêng, p95 **13,5 ms**.
5. (Mở rộng — chỉ khi có use case thật) Dịch vụ GPU tùy chọn dựng 3D từ ảnh/video của cửa hàng/phố/công trình.
6. **Cập nhật 2026-10-11:** lớp ảnh vệ tinh **opt-in** đã tích hợp qua PR #2 (`662a56c`) — MapTiler/XYZ riêng, mặc định tắt, chỉ dùng nguồn được cấp phép; kiến trúc AI/GPU (worker tách rời, chưa triển khai) ghi tại `docs/SATELLITE_AI_GPU_ARCHITECTURE.md`. **Fix 2026-10-11 (PR #5, `a2b1f05`):** endpoint tile sửa sang `maps/satellite/{z}/{x}/{y}.jpg` (đường dẫn cũ `tiles/satellite-v4` trả 404 khi test bằng key thật); đã verify E2E trên browser thật với key MapTiler (zoom 6/17/20 → provider 5/16/19, tile 512px, 0 lỗi).
7. **Cập nhật 2026-10-11:** đồng bộ POI live SSE đã tích hợp qua PR #4 (`7f25705`) — `GET /api/live` chỉ phát revision (không chứa dữ liệu địa điểm), giới hạn 32 stream/tiến trình, client chỉ refresh vùng đang xem; SLO mục tiêu, giới hạn HTTP/1.x và lộ trình mở Internet tại `docs/REALTIME_MAP.md`.

## Điều kiện xem xét lại Map-Anything

- Có yêu cầu thực tế: người dùng tải ảnh/video → xem mô hình 3D.
- Benchmark trên RTX 3090 24GB (VRAM, tốc độ, chất lượng) đạt mức dùng được.
- Triển khai tách dịch vụ riêng hoặc module optional — không nhét vào server chính.
